## Why keys

Every Omarchy theme is a `colors.toml`. When a theme is set, Omarchy fills a template for each app — the terminal, the bar, the window borders, the editor, btop and more — from the keys in that file. So a theme repaints the whole desktop, and anyone can write one.

A bar, a menu or a logo that hard-codes `#82fb9c` looks right in one theme and wrong in the rest. Asking for `accent` instead lets the same design hold in every theme, including ones that don't exist yet.

So the rule is short: **name the key, never the color.** If a key you need is missing, it belongs in this list, not in your file.

Two keys are worked out rather than set: the cursor is always `bright_foreground`, and `selection_background` is another name for `selection`.

## Contrast

A theme can pick any colors it likes, as long as these pairs clear the bar. The ratios are [WCAG 2 contrast ratios](https://www.w3.org/TR/WCAG21/#contrast-minimum): 4.5:1 for text you read, 3:1 for parts of the interface you need to find.

<Pairs />

A theme that misses a **must** is broken for someone. A **should** is a strong default a theme can break on purpose — a low-contrast palette for a dim room, say — but should say so.

`muted` and `dark_foreground` have no minimum. They're for what you can do without: borders, comments, hints. Never let them carry something a person has to read.
